# Feature Development

기능 규모에 따라 절차를 줄일 수 있지만, 요구사항과 검증 없이 구현부터 시작하지 않습니다.

## Workflow

1. Jira 또는 요청에서 목표, 범위, 완료 기준을 확인합니다.
2. 현재 브랜치와 변경사항을 확인합니다.
3. 관련 문서와 가까운 기존 코드를 확인합니다.
4. route, domain, shared 중 코드 소유 위치를 결정합니다.
5. 복잡하거나 애매한 요구사항은 Jira와 사용자에게 제공된 자료를 기준으로 상태와 동작을 먼저 확인합니다.
6. 요청 범위 안에서 구현합니다.
7. 구조, 접근성, 오류 상태와 반응형을 검토합니다.
8. 변경 범위에 맞는 검증을 실행합니다.
9. 구현 내용, 검증 결과와 남은 위험을 정리합니다.

요구사항이 불명확하고 저장소에서도 확인할 수 없으면 추측해서 구현하지 않고 필요한 내용을 질문합니다.

## Completion

- 완료 기준이 코드와 일치합니다.
- 요청 범위 밖 기능이 추가되지 않았습니다.
- 구조나 규칙 변경이 관련 문서에 반영되었습니다.
- 실행한 검증과 생략한 검증이 기록되었습니다.
